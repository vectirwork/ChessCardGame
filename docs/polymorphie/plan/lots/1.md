# Lot 1 : Moteur, cartes et IA

## Objectif
Le moteur obéit aux règles de la partie. Catalogues et équilibrage deviennent des données, les textes des cartes sont produits par gabarits, la décision de l'IA est unique et sait jouer plusieurs cartes. Les anciennes parties se rejouent coup pour coup.

## Étapes
1. Caractérisation : tests qui rejouent test/fixtures/v1/parties et tirages.json, verts avant tout changement.
2. Création des parties :
   - createGame(hands, timed, catalog obligatoire, opts?: { rules }) écrit `rules = stampRules(opts.rules ?? rulesFor('classee'))`, donc rien au défaut ;
   - createGameFromFen avec catalogue obligatoire ; l'ancienne inférence devient une aide nommée (inferCatalog) utilisée par pgn.ts:67 et les tests, pour un comportement identique ;
   - initialStateOf transmet rulesOf(final) ;
   - PGN : en-tête [SpellmateRules "…"] seulement si les règles sont présentes, relu à l'import ; un schéma inconnu donne une erreur explicite.
3. Compteur de cartes :
   - au lancement, k = (cardsThisTurn ?? (cardPlayed ? 1 : 0)) + 1 ; cardPlayed = k ≥ cardsPerTurn ; cardsThisTurn = k écrit seulement si cardsPerTurn > 1 ;
   - finishTurn et probeState effacent cardsThisTurn ;
   - texte du refus par refusBudget(r), identique au défaut ;
   - R4c inchangé ;
   - aucun ajout à Snapshot.
   Ajouter castsThisTurn(s, color) : liste des cartes lancées depuis le dernier coup.
4. Carte à la place du coup :
   - extraire passTurn(n, color, { pawnPush }) du cas de la Marée ;
   - si cardEndsTurn(def, r) : passTurn puis finishTurn ; garde-fous du Rituel pour toute carte qui termine le tour ; demi-coup compté pour les 50 coups hors Marée (Q6).
   info.ritual reste réservé au Rituel : aucun nouveau champ dans CardInfo.
5. Présage : delay lu dans rulesOf(s).presageDelay ; la sonde R4b fait `delay` tickEffects en alternant le lanceur et l'adversaire (identique pour 2) ; profondeur de l'IA selon le délai.
6. Équilibrage par tuneOf : durées (addEffect), rangées (rawCandidates, riftSquares, tidePushes), clockRate. WALL_MATE_PAIRS n'est utilisée que si les rangées du Mur valent [2..5] ; sinon, pas de nulle par matériel insuffisant quand un Mur est posé ou en main.
7. Seuils fiftyHalfmoves et repetitions dans evaluateEnd ; startFen dans createGame (roque standard, refus sinon).
8. CATALOG_RULES remplace les 7 comparaisons de game.ts ; offeredCatalog dérivé de `offered` ; DEFAULT_CATALOG et LEGACY_CATALOG ; drapeau `retired` sur une carte ; suppression de CardDef.catalog.
9. Tirage et choix :
   - dealHands garde ses paramètres positionnels ; ses options gagnent { rules?, deal? } ;
   - validHand avec DEAL.handLimits ; SUSPENDED_CARDS dans cardPool ;
   - draftRefusal(pool, cards, partial, count) avec compte() : « Choisissez 3 cartes. » identique, « 1 carte » correct ;
   - completeDraft(pool, partial, rand, count, limits si limitsInDraft) ;
   - chooseBotDraft(pool, level, rand, { count, limits }) ;
   - DRAFT_VALUE en Record exhaustif sur les Pouvoirs.
10. Codes de refus sur tous les refus, messages identiques.
11. Textes des cartes produits par gabarits (dureeEffet, quiReprend, arriveePresage, rangees), égaux à fixtures/v1/cartes.json ; cardText(id, rules) pour les bulles ; description du catalogue calculée depuis cardsOf.
12. IA :
   - decideTurn(s, level, { cards = true }) dans bot.ts boucle tant que castsLeft > 0 et qu'une carte est jugée utile, dans un seul budget de temps, et rend { cards[], move } ;
   - bot-worker et think l'utilisent et répondent { card: cards[0] ?? null, cards, move } ;
   - askBot(state, level, opts?) dans client/ai/index.ts.
13. Fréquences du tirage calculées par énumération exacte : remplacent la table de climats-random.test.ts:39-44.
