# Lot 9c : Documentation des réglages, README et rapport

Dernier morceau du lot 9 (lots/9.md, étape 7), après la fusion de 9a et 9b et la mesure de performance faite par
l'orchestrateur. Le code est fini : ce lot écrit la documentation, et ne touche au code que pour des commentaires.

## Objectif
Qu'un développeur (ou le fondateur avec un développeur) sache, en une lecture, où et comment changer demain chaque aspect
du site : nombre de cartes, cartes par tour, carte à la place du coup, durées et équilibrage des cartes, Présage,
catalogue, tirage et choix des cartes, cadences, IA, accueil, boutique, marque, routes, interrupteurs, limites, délais,
classement, textes ; ce qui est figé par partie, ce qui change pour tout le monde, ce qui demande une migration.

- docs/REGLAGES.md (nouveau)
- README.md
- docs/polymorphie/ETAT.md et docs/polymorphie/plan/CONCEPTION.md (tableau des modules §2.1 : rulesCore.ts + rules.ts,
  skins/texts.ts, vfx/cardFx.ts, vfx/boardMarks.ts, FriendSheet.tsx, test/fonctions.mjs, test/coherence.test.ts…)
- src/shared/config/index.ts (commentaires seulement, si un renvoi manque)
- test/** seulement pour un test de la documentation (par exemple : chaque réglage cité dans REGLAGES.md existe)

## Étapes
1. Lis le code réel (src/shared/config/*, src/server/settings.ts, src/shared/rules.ts et rulesCore.ts, text/*,
   skins/*, vfx/*, odyssee/data.ts, protocol.ts) : la documentation décrit le code tel qu'il est, pas le plan.
2. docs/REGLAGES.md :
   - « Ce qu'on change demain » : une ligne par besoin courant (« passer à 5 cartes par joueur », « 2 cartes par tour »,
     « une carte remplace le coup », « rééquilibrer le Mur de glace », « Présage en 4 demi-coups », « nouvelle cadence »,
     « couper la boutique », « changer le nom du site », « ajouter un emplacement de skin », « ajouter une carte »,
     « une page de plus »…) : quel fichier, quelle constante, quel test lancer, quelles conséquences (leçons et problèmes
     masqués par `requires`, textes dérivés, captures à regarder, PROTOCOL_VERSION) ;
   - table des réglages : nom, fichier, valeur au défaut, bornes (BOUNDS), portée (par partie figée dans GameState.rules,
     mise en place, plateforme), lu par (serveur, client, build), vérifié par (checkRules, greffon Vite, démarrage) ;
   - règles par contexte (RULES_BY_CONTEXT : accueil, classé, invitation…) et SPELLMATE_TEST_RULES (tests seulement,
     refusé en production) ;
   - garde-fous : checkRules au build, au démarrage et dans les tests ; dettes du garde-fou des textes chiffrés ;
     coherence.test.ts ; témoins v1 (npm run temoins) ; bancs npm run identite et npm run textes-pages (ne jamais lancer
     --ecrire sans décision) ; matrice SPELLMATE_MATRICE ;
   - limites connues et décisions en attente du fondateur (Q1 mentions légales, Q2 prix « compléter » du Trésor, Q5
     textes de marketing, Q11 petites cartes sur mobile à 5 ou 6 cartes, formulation du Présage à délai 4).
3. README.md : section courte « Réglages » qui renvoie à docs/REGLAGES.md ; mettre à jour ce qui a changé (skins,
   profondeur de l'analyse, section « Modifier l'offre » de la boutique avec TRESOR, SHOP_FEATURED, packs, retrait
   d'un objet ; nouvelles commandes npm : temoins, identite, textes-pages, typecheck:concepts, test:matrice…).
4. Vérifie chaque chemin et chaque nom cité (un test peut le faire) ; tsc, vitest et build restent verts.
