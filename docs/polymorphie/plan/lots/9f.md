   le ménage, et le ménage relance l'enregistrement (drapeau `persisting` contre deux essais simultanés). Test qui
   échoue sur le code d'avant : persistance en échec, ménage, rechargement de la salle → toujours terminée, résultat
   inchangé, puis enregistrée quand la base revient.
2. Revanche d'une partie relayée de l'accueil (compatibilité, important) : REVENIR au comportement d'avant la passe
   (choix des cartes, sans relais) : retirer `...setupOf(d)` de l'appel à newRoom de la revanche (garder la pendule
   d'origine `clock`, et les règles du moment, Q3). Corriger commentaires, test (server-regles) et CONCEPTION §2.3.
3. Configuration vérifiée avant le remplacement du site (déploiement, important) : drapeau `--check-config` dans
   src/server/index.ts (sortie 0 juste après startupReport(), avant connectDb ; sortie 1 déjà assurée en cas de
   configuration invalide ou de règles impossibles) ; deploy/update.sh lance
   `$COMPOSE run --rm --no-deps -T app node dist/server/index.js --check-config` entre le build et `up -d`. Test qui
   lit deploy/production.env et l'`environment` de docker-compose.yml et attend 0 erreur de parseEnv. deploy/README.md :
   retour arrière (VERSION doit désigner un commit différent de celui noté comme déployé) et refus de configuration.
4. Maintenance et invitations coupées (sécurité, mineur) : takeSeat refuse un siège quand creationRefusal(room.d,
   identity) n'est pas nul (après la vérification guestOff, qui reste la première) ; joinGame relaie le refus. Identique
   au défaut. Test.
5. File d'attente : le joueur qui attendait et quitte pendant la relecture des sièges n'est pas apparié (correctif du
   constat, avec `queueMatching` pour les deux joueurs). Test avec seatFor différé.

   auth.v). Identique tant que PROTOCOL_VERSION vaut 1.
7. Déconnexion : l'interface ne passe en invité qu'avec l'accord du serveur (store.tsx logout sans finally : succès →
   setMe(null) et toast « À bientôt ! » ; échec → toast d'erreur), comme avant la passe.
8. Rechargement quand un module manque : DecorBoundary (OdysseeHome) recharge le site comme avant si l'erreur est un

9. Documentation seulement (ETAT.md, deploy/README.md, .env.example, REGLAGES.md) : déclarer dans « Écarts voulus » ou
